# AI 마케팅 매니저 데이터 수집 및 기획 전략

## 1. 문서 목적

본 문서는 다음 두 서비스 방향을 결합한 국내 소상공인·중소기업 대상 AI 마케팅 SaaS의 데이터 전략을 정의한다.

- **Predis.ai형 모델**: SNS·블로그 콘텐츠 생성, 이미지 생성, 콘텐츠 캘린더, 예약 발행
- **Vendasta형 모델**: 고객사 다계정 운영, CRM, 마케팅 성과 통합, 대행사·화이트라벨 구조

서비스의 핵심 목표는 단순히 AI로 글을 생성하는 것이 아니다.

> 사업체 정보를 이해하고, 채널별 콘텐츠를 생성하며, 사용자의 승인·수정과 실제 성과를 학습하여 다음 마케팅 실행을 개선하는 운영형 AI 마케팅 매니저를 구축한다.

---

## 2. 핵심 결론

초기 서비스는 인터넷 데이터를 대량 수집해 자체 모델을 학습하는 방식으로 시작하지 않는다.

가장 현실적인 전략은 다음과 같다.

1. 고객사가 제공한 사업·브랜드 정보를 구조화한다.
2. 고객이 연결한 채널과 광고 계정의 데이터를 수집한다.
3. 생성 콘텐츠에 대한 승인·수정 이력을 저장한다.
4. 게시 이후 조회·클릭·문의·예약·구매 성과를 연결한다.
5. 축적된 데이터를 RAG, 추천 규칙, 프롬프트 최적화에 우선 활용한다.
6. 충분한 데이터가 확보된 후 일부 작업에 한해 파인튜닝이나 자체 모델을 검토한다.

초기 경쟁력은 모델의 크기가 아니라 다음 데이터에서 발생한다.

- 고객사가 실제로 승인한 콘텐츠
- 고객이 AI 결과를 어떻게 수정했는지에 대한 기록
- 어떤 콘텐츠가 실제 문의·예약·매출로 이어졌는지에 대한 성과 데이터
- 업종별·채널별로 반복되는 성공 패턴
- 고객사별 브랜드 말투와 금지 표현

# 3. 제품 데이터 전략의 기본 원칙

## 3.1 고객 데이터 우선

외부에서 수집한 일반적인 마케팅 데이터보다 고객이 직접 제공한 사업 정보와 실제 성과 데이터를 우선한다.

외부 데이터는 시장 상황과 아이디어를 보완하는 데 사용하고, 사업체에 대한 사실은 고객 데이터에서 가져온다.

## 3.2 원본과 가공 데이터 분리

외부 API에서 받은 원본 데이터와 서비스 내부에서 정규화·가공한 데이터를 분리한다.

```text
외부 원본 데이터
    ↓
정규화 데이터
    ↓
분석·추천 데이터
    ↓
AI 입력용 컨텍스트
```

원본 데이터는 장애 복구, 재처리, 감사에 사용하고 정규화 데이터는 서비스 기능에 사용한다.

## 3.3 고객사 간 데이터 격리

각 고객사의 사업 정보, 고객 정보, 콘텐츠, 성과 데이터는 논리적 또는 물리적으로 분리한다.

- 모든 주요 테이블에 `tenant_id` 사용
- 벡터 데이터베이스 컬렉션 또는 네임스페이스 분리
- 캐시 키와 파일 저장 경로 분리
- AI 요청 로그에 고객사 식별자를 직접 노출하지 않음
- 다른 고객사의 원문을 프롬프트에 혼합하지 않음

## 3.4 최소 수집

서비스 기능에 필요하지 않은 개인정보는 수집하지 않는다.

예를 들어 마케팅 성과 분석에 고객 전화번호 원문이 필요하지 않다면, 전화번호 대신 내부 고객 식별자와 문의 유형만 저장한다.

## 3.5 사람의 승인 우선

초기 서비스는 AI가 게시물·광고 예산·고객 메시지를 임의로 실행하지 않도록 한다.

```text
DRAFT
→ AI_REVIEWED
→ USER_APPROVED
→ SCHEDULED
→ PUBLISHED
```

광고 예산 변경, 리뷰 답변, 고객 메시지 발송은 별도의 승인 단계를 둔다.

## 3.6 모델 학습 동의와 서비스 이용 동의 분리

고객 데이터를 콘텐츠 생성에 사용하는 것과 서비스 공통 모델 개선에 사용하는 것은 다른 목적이다.

약관과 동의 화면에서는 다음을 구분한다.

- 서비스 제공을 위한 데이터 처리
- 통계·품질 개선을 위한 가명 데이터 활용
- 모델 파인튜닝을 위한 학습 데이터 활용
- 제3자 AI API 전송
- 외부 채널 API 연동

# 4. 수집해야 할 데이터 분류

## 4.1 사업체 기본 데이터

고객 온보딩 과정에서 직접 입력받는 데이터다.

| 구분 | 주요 항목 | 사용 목적 |
|---|---|---|
| 사업체 | 상호명, 업종, 지역, 영업시간 | 기본 콘텐츠 생성 |
| 상품·서비스 | 명칭, 가격, 특징, 판매 기간 | 상품 소개, 광고 문구 |
| 고객층 | 연령, 직업, 방문 목적, 지역 | 타깃별 메시지 생성 |
| 브랜드 | 말투, 가치, 색상, 폰트, 로고 | 일관된 콘텐츠 생성 |
| 금칙 정보 | 금지 표현, 과장 표현, 민감 문구 | 자동 검수 |
| 프로모션 | 할인, 이벤트, 쿠폰, 기간 | 캠페인 콘텐츠 |
| 연락 정보 | 대표 연락처, 예약 링크, 위치 | CTA 자동 생성 |
| 경쟁사 | 상호 또는 공개 URL | 비교·시장 조사 |
| FAQ | 문의와 표준 답변 | 상담 및 콘텐츠 소재 |
| 법적 고지 | 필수 문구, 면책 문구 | 업종별 준수 |

### 예시

```json
{
  "business_id": "biz_001",
  "business_name": "마포 바닐라 카페",
  "industry": "cafe",
  "service_area": "서울 마포구",
  "target_segments": [
    "20~30대 직장인",
    "인근 거주자"
  ],
  "brand_tone": [
    "친근함",
    "차분함",
    "과장 표현 금지"
  ],
  "prohibited_phrases": [
    "최고",
    "무조건",
    "서울 1위"
  ]
}
```

## 4.2 브랜드 자료와 내부 문서

고객이 보유한 문서를 업로드받아 브랜드 지식베이스로 사용한다.

### 수집 대상

- 회사 소개서
- 메뉴판과 가격표
- 상품 카탈로그
- 서비스 설명서
- 기존 블로그 글
- 기존 SNS 게시물
- 광고 문구
- 상담 스크립트
- 자주 묻는 질문
- 환불·예약·배송 정책
- 로고와 브랜드 가이드
- 제품·매장 이미지

### 처리 방식

```text
파일 업로드
→ 파일 유형 검사
→ 텍스트·메타데이터 추출
→ 개인정보와 민감정보 탐지
→ 문서 단위 저장
→ 문단 단위 분할
→ 임베딩 생성
→ 고객사별 벡터 저장소 등록
```

초기에는 해당 자료를 모델 재학습에 사용하지 않고 RAG 지식베이스로 사용한다.

## 4.3 콘텐츠 데이터

AI가 생성한 초안부터 실제 게시된 최종본까지 전체 이력을 저장한다.

| 단계 | 저장 데이터 |
|---|---|
| 생성 요청 | 목적, 채널, 상품, 대상 고객, 캠페인 |
| AI 생성 | 모델, 프롬프트 버전, 원본 출력 |
| 자동 검수 | 금칙어, 길이, 중복, 필수 문구 검사 |
| 사용자 편집 | 수정 전후 문장, 수정 범위 |
| 승인 | 승인자, 승인 시각, 거절 사유 |
| 발행 | 채널, 게시 시각, 외부 게시물 ID |
| 성과 | 노출, 클릭, 반응, 문의, 구매 |

### 반드시 보존할 핵심 항목

```json
{
  "content_id": "cnt_001",
  "tenant_id": "tenant_001",
  "channel": "instagram",
  "generated_text": "AI가 최초로 생성한 문장",
  "final_text": "사용자가 수정하고 승인한 문장",
  "approval_status": "approved",
  "edit_distance": 0.27,
  "feedback_reason": "과장 표현 제거",
  "prompt_version": "sns_caption_v3",
  "model_route": "bulk_writer",
  "published_at": "2026-08-05T18:00:00+09:00"
}
```

## 4.4 채널 성과 데이터

채널마다 지표 이름과 정의가 다르므로 공통 지표로 정규화한다.

### 공통 지표

- `impressions`: 노출 수
- `reach`: 고유 도달 수
- `engagements`: 좋아요·댓글·저장·공유 등
- `clicks`: 링크 클릭
- `inquiries`: 문의
- `reservations`: 예약
- `orders`: 주문
- `revenue`: 매출
- `ad_spend`: 광고비
- `conversions`: 정의한 전환
- `review_count`: 리뷰 수
- `average_rating`: 평균 평점

### 플랫폼 원본도 함께 보관

```json
{
  "platform": "instagram",
  "external_content_id": "external_123",
  "normalized_metrics": {
    "impressions": 3100,
    "engagements": 152,
    "clicks": 41,
    "conversions": 3
  },
  "raw_metrics": {
    "likes": 94,
    "comments": 11,
    "saves": 28,
    "shares": 19
  }
}
```

## 4.5 광고 데이터

광고 기능을 제공할 경우 다음 정보를 수집한다.

- 캠페인·광고그룹·소재 ID
- 목표
- 타깃 조건
- 예산
- 입찰 방식
- 광고 문구와 이미지
- 노출·클릭·비용
- 전환
- 전환 매출
- 광고수익률
- 변경 이력
- AI 추천과 사용자 승인 여부

### 초기 주의사항

AI가 바로 예산을 변경하지 않고 다음과 같이 제안형으로 운영한다.

```text
광고 성과 하락 감지
→ 원인 요약
→ 예산 또는 소재 변경안 제안
→ 사용자 승인
→ 광고 API 실행
→ 결과 기록
```

## 4.6 CRM과 고객 반응 데이터

Vendasta형 구조를 확장하려면 고객 접점 데이터가 필요하다.

### 수집 대상

- 문의 채널
- 문의 시각
- 문의 유형
- 상담 상태
- 예약 여부
- 구매 여부
- 재방문 여부
- 쿠폰 발급·사용 여부
- 리뷰 요청·작성 여부
- 캠페인 유입 경로

### 개인정보 최소화 예시

```json
{
  "customer_ref": "customer_hash_82",
  "inquiry_category": "reservation",
  "source_channel": "kakao",
  "converted": true,
  "conversion_type": "booking",
  "personally_identifiable_text_removed": true
}
```

상담 원문 전체를 장기간 저장하기보다 필요한 정보만 추출한 후 원문 보존 기간을 짧게 설정하는 방식이 적절하다.

# 5. 데이터 수집 경로

## 5.1 수동 입력

MVP에서 가장 우선해야 하는 방식이다.

### 장점

- 개발이 빠름
- API 승인 문제 없음
- 고객이 데이터 정확성을 직접 확인 가능
- 채널별 제한에 덜 의존함

### 구현 항목

- 온보딩 설문
- CSV 업로드
- 문서 업로드
- 이미지 업로드
- 기존 게시물 붙여넣기
- 상품 일괄 등록
- 브랜드 규칙 입력
- 경쟁사 URL 등록

## 5.2 공식 API 연동

API 연동은 고객이 계정을 연결하고 접근 권한을 명시적으로 허용한 경우에만 진행한다.

| 연동 대상 | 수집 가능 데이터 | 권장 단계 |
|---|---|---:|
| GA4 Data API | 웹·앱 사용자, 페이지, 이벤트, 전환, 매출 | 2단계 |
| Google Business Profile | 사업장 정보, 리뷰, 성과 보고서 | 2단계 |
| 네이버 검색광고 API | 광고 계정·캠페인·성과 보고서 | 2~3단계 |
| 네이버 커머스 API | 스마트스토어 상품·주문 등 | 쇼핑몰형 2단계 |
| 카카오톡 채널 API | 채널 관계, 고객파일 관리 | 3단계 |
| 카카오모먼트 API | 광고·메시지 광고 운영 | 3~4단계 |
| Meta/Instagram | 게시·인사이트·광고 데이터 | 2~3단계 |
| Google Ads | 캠페인·광고·비용·전환 | 3~4단계 |

Google Analytics Data API는 GA4 보고서 데이터를 프로그래밍 방식으로 조회하고 대시보드·자동 보고서·다른 업무 시스템과의 연동에 사용할 수 있다.[^1]

Google Business Profile API는 사업장 계정과 위치 정보를 관리하며 리뷰와 성과 데이터용 API를 별도로 제공한다.[^2]

네이버 검색광고 API는 광고주센터에서 API 라이선스와 비밀키를 발급받아 사용한다.[^3]

네이버 커머스 API는 커머스 API 센터에서 애플리케이션 등록과 인증 절차를 거쳐 스마트스토어 주요 기능을 연동한다.[^4]

카카오톡 채널 API는 채널 추가 관계 조회와 고객파일 관리 기능 등을 제공하지만, 일반적인 대량 메시지 발송 기능과 동일한 API가 아니다. 메시지 광고 기능은 카카오모먼트 측 권한과 비즈니스 설정이 별도로 필요하다.[^5][^6]

---

## 5.3 웹 검색 API

최신 뉴스, 트렌드, 지역 행사, 공개 경쟁 정보를 조사할 때 사용한다.

### 원칙

- 검색 결과를 그대로 학습 데이터로 축적하지 않음
- 출처와 조회 시각 저장
- 콘텐츠 생성 시 최신성 검증
- 원문 전체가 아니라 요약·특징·링크 메타데이터 저장
- 저작권 또는 이용약관에서 금지한 방식으로 수집하지 않음

## 5.4 크롤링

크롤링은 공식 API나 고객 제공 방식으로 해결할 수 없는 경우에만 제한적으로 검토한다.

### 크롤링 전 확인 항목

- 공개 페이지인지
- 로그인 또는 우회 접근이 필요한지
- 서비스 약관에서 자동 수집을 제한하는지
- robots.txt와 호출 빈도
- 개인정보 포함 여부
- 저작권이 있는 원문을 대량 저장하는지
- 데이터 사용 목적과 보존 기간
- 공식 API 또는 제휴 방식이 존재하는지

### 하지 말아야 할 방식

- 로그인 쿠키를 받아 비공개 화면 수집
- CAPTCHA 우회
- 차단 회피를 위한 프록시 순환
- 개인 계정 프로필 대량 수집
- 리뷰 작성자 이름과 프로필을 불필요하게 보관
- 경쟁사 글과 이미지를 그대로 복제해 콘텐츠 생성
- 채널의 비공개 분석 데이터를 무단 수집

# 6. 채널별 현실적인 수집 전략

## 6.1 네이버 블로그

### MVP

- 고객이 기존 글 URL 또는 텍스트를 등록
- 고객이 내보낸 글 목록을 CSV로 업로드
- 제목·본문·게시일·카테고리 분석
- AI가 글을 생성하고 사용자가 직접 발행
- 발행 후 URL을 서비스에 등록

### 확장

- 공식 제공 범위 또는 제휴 가능성 검토
- 검색 결과 기반 노출 추적
- 네이버 검색광고 데이터와 결합
- 블로그 유입을 GA4 또는 랜딩 페이지에서 추적

### 주의

네이버 블로그 자동 게시와 상세 성과 수집은 일반 공개 API만으로 제품이 요구하는 전체 기능을 구현하기 어려울 수 있다. 서비스 기획 단계에서 자동 발행을 확정 기능으로 간주하지 말고, **복사·발행 보조 또는 브라우저 확장 기능**을 대안으로 둔다.

# 10. AI 활용 전략

## 10.1 초기: RAG와 프롬프트 조합

초기에는 다음 정보를 AI 요청 시 조합한다.

```text
브랜드 프로필
+ 관련 상품
+ 과거 승인 콘텐츠
+ 최근 성과가 좋았던 콘텐츠
+ 채널 규칙
+ 캠페인 목표
+ 최신 시장 정보
```

이를 통해 모델을 직접 학습하지 않고도 고객사별 결과를 만들 수 있다.

## 10.2 고객사별 선호 규칙 생성

사용자가 반복적으로 수정한 패턴을 요약한다.

```json
{
  "tenant_id": "tenant_001",
  "learned_preferences": [
    "과장 표현을 사용하지 않음",
    "문장은 2~3줄 단위로 작성",
    "가격은 본문 후반에 표시",
    "이모지는 게시물당 최대 2개",
    "직접 만든 재료를 우선 강조"
  ]
}
```

이 규칙은 프롬프트에 반영하되 사용자가 직접 확인하고 수정할 수 있도록 한다.

## 10.3 성과 기반 콘텐츠 검색

새 콘텐츠 생성 시 단순히 과거 글 전체를 참조하지 않는다.

다음 조건으로 검색한다.

- 같은 업종
- 같은 채널
- 같은 상품 또는 캠페인 유형
- 동일 고객사
- 최근 기간
- 승인된 콘텐츠
- 성과 상위 콘텐츠
- 정책 위반이 없는 콘텐츠

## 10.4 모델 파인튜닝 시점

다음 조건이 충족되기 전에는 파인튜닝을 우선하지 않는다.

- 동일한 작업 유형 데이터가 충분히 누적됨
- 입력과 정답 형식이 안정됨
- 사람의 승인 품질이 일정함
- 데이터 사용 동의가 명확함
- 프롬프트와 RAG만으로 해결하기 어려운 반복 문제가 확인됨
- 비용 절감 또는 형식 준수 개선 효과를 측정할 수 있음

### 파인튜닝 후보 작업

- 고객 문의 분류
- 리뷰 감성·주제 분류
- 업종별 게시물 형식 생성
- 브랜드 문체 변환
- 금칙 문장 탐지
- 광고 소재 태깅

### 초기 파인튜닝에 부적합한 작업

- 최신 시장 조사
- 사실 확인이 필요한 장문 블로그
- 고객사별 정보가 수시로 바뀌는 콘텐츠
- 법률·의료·금융 표현 검수
- 소수 고객 데이터만 존재하는 작업

가명정보를 활용하더라도 재식별 위험, 처리 목적, 결합 가능성, 안전조치와 적정성 검토가 필요하다.[^9]

# 18. 제품 기획 권고안

## 18.1 첫 번째 제품 가설

> 사업자가 15분 안에 사업 정보를 등록하면 AI가 한 달의 콘텐츠 계획과 첫 주 게시물을 만들고, 사용자가 수정·승인할 수 있다.

초기에는 “AI가 모든 마케팅을 대신한다”보다 “마케팅 준비 시간을 줄여준다”는 가치가 검증하기 쉽다.

## 18.2 두 번째 제품 가설

> 사용자가 AI 문구를 수정할수록 서비스가 브랜드 선호를 학습하여 수정 시간이 감소한다.

측정 지표:

- 콘텐츠당 평균 편집 시간
- 편집 거리
- 수정 없이 승인된 비율
- 재생성 횟수

## 18.3 세 번째 제품 가설

> 실제 성과 데이터를 연결하면 일반적인 생성 도구보다 다음 콘텐츠 추천의 품질이 높아진다.

측정 지표:

- 콘텐츠 발행률
- 참여율 개선
- 문의·예약 증가
- 추천 콘텐츠 채택률
- 성과 상위 패턴 재사용률

## 18.4 대행사 확장 가설

> 대행사는 AI 생성 기능보다 고객사별 자료 정리, 승인, 일정, 보고서, 비용 관리에서 더 큰 가치를 느낀다.

따라서 Vendasta형 기능은 생성 AI 이후가 아니라, 초기 데이터 구조부터 다중 고객사를 고려해야 한다.

# 19. 최종 권장 구조

```text
[고객 사업 데이터]
        +
[채널·광고·CRM 데이터]
        +
[사용자 승인·수정 데이터]
        +
[검색·시장·공공 데이터]
        ↓
[고객사별 지식베이스]
        ↓
[마케팅 기획 AI]
        ↓
[채널별 콘텐츠 생성]
        ↓
[규칙 검사와 사용자 승인]
        ↓
[게시·광고·메시지 실행]
        ↓
[성과 데이터 수집]
        ↓
[다음 마케팅 계획 개선]
```

서비스의 장기 경쟁력은 특정 LLM에 종속되지 않는다.

가장 중요한 자산은 다음 네 가지다.

1. 고객사별 구조화된 사업·브랜드 지식
2. AI 초안과 사용자 최종본의 차이
3. 콘텐츠와 실제 성과의 연결 데이터
4. 업종별로 검증된 마케팅 워크플로와 평가 기준

따라서 첫 개발 단계에서는 모델을 많이 연결하는 것보다 **데이터 구조, 승인 이력, 성과 연결, 고객사 격리**를 먼저 완성하는 것이 합리적이다.
